<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Client/proxy headers → quota identity | Forwarded identity can be spoofed without a trusted-hop contract. |
| API → public internet | User URLs can target internal networks or malicious media. |
| Multiple API instances → PostgreSQL | Quota increments must remain atomic under concurrency. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-20 | Spoofing | Forwarded client IP | high | mitigate | Trust only configured proxy hops; direct address otherwise. |
| T-02-21 | Tampering | Rate window | high | mitigate | PostgreSQL atomic operation and validated server config. |
| T-02-22 | Information disclosure | SSRF | critical | mitigate | Per-hop DNS/IP/pinning/redirect controls and redacted errors. |
| T-02-23 | Denial of service | Scan/mirror abuse | high | mitigate | 20/10m IP and 50/10m user quotas before outbound work. |
| T-02-24 | Elevation of privilege | Mirror owner | high | mitigate | Session user is the sole authenticated quota/asset subject. |
| T-02-SC | Tampering | Package installation | high | mitigate | PostgreSQL and existing runtime utilities only. |
</threat_model>
